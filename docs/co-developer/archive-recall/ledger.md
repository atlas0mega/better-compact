Tradeoff: full recovery can take multiple calls; pending descriptions are visible only as status in explicit catalog discovery until validated.
- **P-003: Safe archive/handoff transaction and migration.** Write a private exact delta archive and catalog record atomically before hiding any older live wording; mark it ready only after valid Luna output. Track a monotonically increasing successful **validated-handoff** compaction generation, so messages archived in generation 1 retire live only after generation 2 has a valid current-intent handoff. Carry the preceding task-state checkpoint forward and clear per-turn cache entries only once actually absorbed; preserve needed active per-turn entries on non-prefix plans. Existing cumulative archives remain read-only for older snapshots during migration; don't delete them or blindly adopt the preliminary dirty source edits. ## 5. Requirements and acceptance criteria

- **R-001 (D-001, D-009):** The first successful compaction writes exact newly covered native messages to one private delta archive; a second compaction writes its new delta, not the first archive again (except a complete message that straddles a split boundary). Archive IDs and session order identify each delta; every archived byte is recoverable through explicit pages.
- **R-002 (D-002, D-005, D-009):** Retain ordinary older user wording in the live handoff through compaction 1; **compaction 2's** valid task-state handoff may retire that wording even if compaction 1 was cheap-only. Goals, still-active constraints, corrections, decisions, failures and next step remain intelligible; the archive preserves literal text. A failed Luna handoff never authorizes retirement.
- **R-003 (D-003, D-007, D-010):** Each ready archive has a Luna-written description ≤100 words and stable ID. At most five newest ready ID/descriptions appear in the stable prompt, separately from the current task handoff; a tool catalog can list older entries. Pending archives cannot masquerade as valid Luna descriptions.
- **R-004 (D-006, D-011, D-012):** No automatic archive reads or injected excerpts. A session-linked tool requests read permission, validates the requested archive belongs to that session or a content-validated inherited fork, and returns bounded excerpts/pages; subagent catalogs stay separate. A normal continuation with enough live task state makes zero recall calls; exact old wording remains accessible by ID and page.
- **R-005 (D-008, D-015):** Deterministic reductions precede Luna, then at most five model calls **including** descriptions, final handoff and retries; at most three attempts per failed job including the first. Preserve a final aggregation slot; a retry is skipped if it would make completion impossible within budget. Stable replay makes zero new summary calls.
- **R-006 (D-012):** Private archive/index files stay until explicit deletion; a fork inherits only content-validated read-only links, not a project-wide catalog. Failure or unavailable permission returns a bounded error without leaking raw history.
- **R-007 (D-013):** Aim near the configured 22% target without a hard numeric pass band or truncating active intent. Report the **final applied** projection, residual vs target, irreducible causes and summary failures, not misleading intermediate gains. Prefer cheap deterministic pruning; do not repeat Luna work on stable replay.
- **R-008 (D-018):** Before aggressive old-user retirement is enabled, mock/fixture tests prove exact delta coverage, prompt-cache-stable replay, lineage/permission boundaries, failure fallback, and best-effort reduction; an authorized live Luna run demonstrates at least one valid description plus current-intent handoff. If unavailable, rollout remains archival-only rather than pretending success.
- **R-009 (user-requested automatic-compaction fix; diagnostic gate pending):** When automatic compaction is enabled, permission is allow, and either the provider-reported usage or raw estimate of a **continuing assistant/tool-loop request** crosses the model's configured trigger, the next ordinary model request must receive a newly built or valid replayed Better Compact plan **before** calling the provider, without requiring a fresh human message. If a host early branch prevents that hook, use a supported safe seam for that branch; if the hook ran but refused a plan, expose the actual no-op reason. A terminal assistant response with no subsequent model request need not compact immediately. Regression coverage must include assistant-last history, tool-result continuation, no-human request boundaries, pre-request trigger crossing, provider usage vs raw estimate, subagent, permission, missing model limit, and cached-plan replay. Do not alter thresholds or add on-every-token model calls just to mask the failure.
